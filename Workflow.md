# Как работать над проектом

## Окружение

Для удобства работы над проектом используются инструменты из **Node.js** и **npm**. Все необходимые настройки произведены. Убедитесь, что на рабочем компьютере установлен актуальный LTS релиз Node.js**. Актуальная версия **Node.js** указана в файле `package.json` в поле `node`. Затем, в терминале, перейдите в директорию с проектом и _единожды_ запустите команду:

```bash
npm install
```

Команда запустит процесс установки зависимостей проекта из **npm**.

### Сценарии

В `package.json` предопределено несколько сценариев.

#### Запустить CLI

```bash
npm run cli -- --help
```

Собирает проект и запускает CLI. Аргументы после `--` передаются приложению.
Без аргументов CLI выводит справку.

#### Запустить сервер тестовых данных

```bash
npm run mock:server
```

Запускает JSON-server на адресе `127.0.0.1` и порту 3000 с данными из `mocks/mock-server-data.json`.
Заготовки для генерации предложений доступны по адресу http://127.0.0.1:3000/data.
Сервер подхватывает изменения JSON-файла благодаря параметру `--watch`.
Для остановки сервера нажмите `Ctrl + C` в терминале.

#### Скомпилировать проект

```bash
npm run compile
```

Создаст директорию `dist` и скомпилирует проект.

#### Удалить скомпилированный проект

```bash
npm run clean
```

Удаляет директорию `dist`. Используется перед компиляцией.

#### Собрать проект

```bash
npm run build
```

Выполняет сборку проекта: удаляет ранее скомпилированный проект и компилирует заново.

#### Проверить линтером

```bash
npm run lint
```

Запуск проверки проекта статическим анализатором кода **ESLint**.

Линтер проверяет файлы только внутри директории `src`.

**Обратите внимание**, при запуске данной команды, ошибки выводятся в терминал.

#### Запустить ts-модуль без компиляции

```bash
npm run ts -- <Путь к модулю с ts-кодом>
```

Пакет `ts-node` позволяет выполнить TS-код в Node.js без предварительной компиляции. Используется только на этапе разработки.

#### Запустить проект

```bash
npm start
```

В процессе запуска проекта будет выполнен процесс «Сборки проекта» и запуска результирующего кода.

## Запуск проекта

Из корня репозитория установите зависимости командой `npm install`.
CLI запускается отдельным сценарием:

```bash
npm run cli
npm run cli -- --help
npm run cli -- --version
npm run cli -- --import mocks/offers.tsv "mongodb://admin:PASSWORD@127.0.0.1:27017/six-cities?authSource=admin"
```

`--version` читает версию из `package.json`. `--import` принимает два аргумента:
путь к TSV и полный URI MongoDB. В примере замените `PASSWORD` паролем
из `.env`; там же задайте `SALT` для хеширования паролей авторов.
Команда читает файл потоком и сохраняет каждое предложение в MongoDB.
Существующие авторы находятся по email, новые создаются один раз.
В консоль выводятся прогресс через каждые 100 000 записей и итоговые
количества предложений и новых пользователей. Документы и пароли
в вывод не включаются. Предложения обрабатываются по одному.
Повторный импорт добавляет предложения заново, а авторов использует повторно.

### Генерация тестовых предложений

В одном терминале запустите сервер заготовок:

```bash
npm run mock:server
```

Во втором терминале из корня проекта запустите генерацию:

```bash
npm run cli -- --generate 5 generated/offers.tsv http://127.0.0.1:3000/data
```

Аргументы команды: положительное целое количество предложений, путь к новому
TSV-файлу и HTTP/HTTPS адрес сервера заготовок. Сервер должен вернуть объект
с массивами `titles`, `descriptions`, `cities`, `housingTypes`, `amenities`,
`images`, `authors`, как в `mocks/mock-server-data.json` внутри поля `data`.
Указывайте адрес ресурса `/data`, чтобы получить этот объект.

Команда проверяет заготовки и записывает предложения через поток, создавая
нужные папки автоматически. Существующий файл не перезаписывается:
для повторного запуска выберите новое имя. Ошибки запроса, данных и записи
приводят к завершению с кодом 1. После успешной записи выводится число предложений.

Импортировать результат в MongoDB можно командой:

```bash
npm run cli -- --import generated/offers.tsv "mongodb://admin:PASSWORD@127.0.0.1:27017/six-cities?authSource=admin"
```

Относительный путь к TSV отсчитывается от текущей папки терминала. Путь с
пробелами заключайте в кавычки. При ошибке приложение выводит сообщение и
завершается с кодом 1.

### Проверка больших файлов

На предыдущем этапе проверялось потоковое чтение файла с 4 500 000
предложений (2 477 187 569 байт, около 2,31 GiB). Эта проверка выполнялась
до добавления записи в MongoDB и не является проверкой массового сохранения.
Сгенерированные файлы находятся в `generated/` и не включаются в Git.
Для нового запуска с записью в MongoDB используйте:

```bash
npm run cli -- --generate 4500000 generated/big-offers.tsv http://127.0.0.1:3000/data
npm run cli -- --import generated/big-offers.tsv "mongodb://admin:PASSWORD@127.0.0.1:27017/six-cities?authSource=admin"
```

При повторной генерации выберите свободное имя файла. Запись миллионов
предложений потребует времени и места на диске; для обычной проверки
используйте небольшой TSV.

### Формат тестового файла

Сгенерированные TSV-файлы сохраняйте в директории `generated/` в корне проекта.
Она исключена из Git, чтобы результаты генерации не попали в коммиты.

`mocks/offers.tsv` содержит два предложения. Каждая запись занимает одну строку,
поля разделены табуляцией. Заголовка и комментариев нет.

Порядок 21 колонки:

1. Название.
2. Описание.
3. Дата публикации в формате ISO 8601.
4. Город.
5. Путь к превью.
6. Шесть путей к фотографиям, разделённых `;`.
7. Премиум: `true` или `false`.
8. Избранное: `true` или `false`.
9. Рейтинг, десятичный разделитель — точка.
10. Тип жилья.
11. Количество комнат.
12. Количество гостей.
13. Стоимость аренды.
14. Удобства, разделённые `;`.
15. Имя автора.
16. Email автора.
17. Путь к аватару автора; поле может быть пустым.
18. Тестовый пароль автора.
19. Тип пользователя: `regular` или `pro`.
20. Широта.
21. Долгота.

Количество комментариев устанавливается в 0. Пути `img/...` в тестовом файле
ссылаются на изображения готовой вёрстки в `markup`.

## Структура проекта

### Директория `src`

Исходный код проекта: компоненты, модули и так далее. Структура директории `src` может быть произвольной.

### Файл `Readme.md`

Инструкции по работе с учебным репозиторием.

### Файл `Contributing.md`

Советы и инструкции по внесению изменений в учебный репозиторий.

### Остальное

Все остальные файлы в проекте являются служебными. Пожалуйста, не удаляйте и не изменяйте их самовольно. Только если того требует задание или наставник.
